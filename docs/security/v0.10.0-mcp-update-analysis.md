1. **Model Context Protocol (MCP) 深度支援** 與 **Code Mode 架構整合**（詳見 [ADR 0006](../../docs/adr/0006-mcp-and-code-mode.md)）。

## 2. 核心功能與架構變更 (Core Changes)

### 2.1 MCP 伺服器與 Code Mode 支援 (ADR 0006)
- **視覺化管理介面 (`Settings › MCP`)**：
  - 支援全域與專案層級的 MCP 伺服器新增與編輯。
  - 支援快速導入：貼上 Claude Desktop、Cursor、VS Code 設定 JSON 或 CLI 命令（如 `npx -y @modelcontextprotocol/...`）即可自動解析。
  - 連線測試與 OAuth 流程：提供連線測試端點 (`/api/mcp/test`) 與 OAuth 授權登入/登出端點 (`/api/mcp/sign-in`)。
- **曝光範圍控制 (Exposure Control)**：
  - `Direct`：將工具直接加入模型 Context Window。
  - `Code mode`：將工具包裝進腳本環境，模型透過撰寫腳本搜尋並調用工具，降低 Token 消耗。
  - `Hidden`：停用並隱藏該伺服器。
- **唯讀保護政策 (Read-only Policy)**：
  - 在唯讀模式（Read-only Session）中，自動阻擋未標註 `readOnlyHint` 的 MCP 工具。

### 2.2 UI 與對話體驗改進
- **執行中分支對話 (Fork Session mid-run)**：支援在 Agent 正在生成輸出時直接 Fork 對話分支 (`#1023`)。
- **串流中動態調整思考等級 (Reasoning Level mid-stream)**：支援在生成中動態變更推理等級 (`#1022`)。
- **檔案瀏覽與管理強化**：
  - 檔案樹自動遵從 `.gitignore` 隱藏忽略檔案 (`#1014`)。
  - 目錄選擇器新增即時建立子資料夾功能 (`#981`)。
  - 新增系統檔案總管開啟按鈕 (`#907`)。
  - 支援自訂訊息發送鍵（Enter / Ctrl+Enter）。

## 3. 安全性強化評估 (Upstream Security Hardening)

本次更新中，upstream 官方主動引入了數項重要的安全防護機制：

1. **stdio MCP 子行程環境變數清洗 (Scrub Environment Variables)**：
   - 啟動 stdio MCP 伺服器時，強制設定 `inheritEnv: false`，清洗所有傳入的環境變數。
   - **阻斷敏感資訊外洩**：徹底杜絕 `PI_WEB_PASSWORD`、`PORT`、`NEXT_*` 等被惡意或第三方 MCP 行程讀取的風險；並在設定端阻擋手動引用 `PI_WEB_PASSWORD`。
2. **專案信任邊界強化 (Project Trust)**：
   - 專案內部 `.pi/mcp.json` 在未受信任（Untrusted）狀態下不會自動載入。
   - 建立新目錄時導入 Fresh Folder 信任防護；加固異常 JSON 容錯，防止惡意設定檔導致伺服器崩潰。
3. **檔案 API 授權與路徑檢驗收斂**：
   - `/api/files/[...path]` 新增 `hasParentDirectorySegment` 檢查，防範 URL 編碼之目錄穿越攻擊。
   - 移除對 System Message 與非程式碼工具輸回路徑的信任授權。
4. **本機總管端點限制 (`/api/open-in-explorer`)**：
   - 端點內部使用 `isLoopbackHost` 嚴格限制，僅允許來自 `127.0.0.1` / `::1` 之請求調用，拒絕外部或 LAN 網路觸發本地檔案總管。

## 4. 先前安全審計漏洞比對 (Audit Findings Delta)

與先前在 `v0.9.3` 完成之原始碼安全審計比對，各漏洞於 `v0.10.0` 中的現況如下：

| 漏洞編號 | 漏洞名稱 | 嚴重程度 | v0.10.0 現況與影響 |
| :--- | :--- | :---: | :--- |
| **VULN-01** | `/api/cwd/validate` 任意擴展根目錄導致白名單逃逸 | **High** (8.2) | **未修復**。前端仍可透過驗證端點將磁碟根目錄加入允許清單。 |
| **VULN-02** | 模型探索端點 SSRF (伺服器端請求偽造) | **High** (7.5) | **未修復**。自訂 Provider 探索未防護 Private IP / AWS Metadata (169.254.169.254)。 |
| **VULN-03** | 全域外掛安裝繞過信任限制 (供應鏈 RCE) | **High** (7.2) | **未修復**。全域安裝仍缺乏二次授權與 `--ignore-scripts`。 |
| **VULN-04** | 預設無認證 + LAN 暴露 + 內建 PTY 終端 | **Critical** (9.8) | **未修復**（架構固有行為）。預設仍無密碼，非 loopback 監聽時仍具未授權 Web Shell 風險。 |
| **VULN-05** | 缺失全域防點擊劫持標頭 (Clickjacking) | **Medium** (6.5) | **未修復**。`next.config.ts` 仍未配置 `frame-ancestors` 與 `X-Frame-Options`。 |
| **VULN-06** | `GET /api/models-config` 明文輸出 API Key | **Medium** (6.5) | **未修復**。API 回應未遮罩自訂 Key。 |
| **VULN-07** | `/api/skills/install` CLI 參數注入潛在風險 | **Medium** (5.3) | **未修復**。尚未加上減號開頭過濾。 |

## 5. 結論與建議

1. **基礎升級價值**：`v0.10.0` 是重要的架構升級，MCP 與 Pi 1.0 的整合使專案具備更強大的工具生態。
2. **安全態勢**：雖然官方強化了 MCP 子行程與 Project Trust 的防禦，但先前審計發現的核心高危漏洞（`VULN-01` 根目錄逃逸、`VULN-02` SSRF、`VULN-05` 防點擊劫持）在 `v0.10.0` 依然存在。
3. **維護與修復建議**：
   - 後續若進行 Fork 或向上游提交 PR，應以 `v0.10.0` 為基準分支。
   - 原先規劃之獨立修復 PR（限制 `/api/cwd/validate` 根目錄、補齊全域 CSP 標頭、模型端點 SSRF 阻擋）與 `v0.10.0` 架構高度相容，可直接應用。
